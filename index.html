A transformer processes all words at once. How does it know which word came first? The answer used in almost every modern language model (LLaMA, Mistral, GPT-4) is RoPE: instead of stamping a position number onto each word, it rotates the word's internal representation by an angle that encodes its position. This page walks you through exactly why that works in an interactive way.

Section 01: The Problem

Why Transformers Can't Tell Words Apart by Order

Before we can understand RoPE, we need to understand the problem it solves. Let's start with two key ideas: tokens and attention.

What is a token?

A token is the smallest chunk the model works with. It is usually a word or a common piece of a word, for example "running" becomes "run" plus "ning". Each token gets converted into an embedding: a list of hundreds of numbers that encode its meaning. Think of it as the token's "personality" in math form.

What is attention?

Self attention is how a transformer lets every token "look at" every other token. To attend to a token, the model computes a similarity score between the current token and all others, then uses those scores to blend information from across the sequence. This is what lets "bank" in "river bank" use the surrounding words to understand it means riverbank, not a financial bank.

So what's the problem?

Attention scores are computed by taking a dot product (multiply and sum) between query and key vectors. That comparison can tell whether two token vectors match, but it has no built in slot for "this word came first." Unless position is added somehow, the same words keep the same pairwise scores even when their order changes.

This means: without extra help, "The cat chased the dog" and "The dog chased the cat" contain the same token identities, but the role of each word depends on order. The model needs a position signal to tell subject, verb, and object apart.

So how do we fix it?
1
We inject a position signal into each token's embedding before computing attention. The signal tells the model "this is the 3rd word" or "this is the 7th word."
2
The challenge: the signal must preserve the token's existing meaning while making relative positions easy to use ("these two words are 4 apart") as well as absolute positions ("word is at position 7").
3
Two approaches have been tried: Sinusoidal PE (add a fixed position vector to each embedding) and RoPE (rotate the vectors instead of adding). The next two sections explore both.
Section 02: The Old Approach

Standard Sinusoidal Positional Encoding

The original Transformer paper (Vaswani et al., 2017) proposed a simple fix: for each position in the sequence, create a unique vector of numbers using sine and cosine waves, then add that vector to the token's embedding.

The Formula

PE(pos, 2i) = sin( pos / 100002i/d )
PE(pos, 2i+1) = cos( pos / 100002i/d )
Then: new_embedding = token_embedding + PE(pos, :)

Here's what each term means:

pos The token's position in the sequence. Use 0 for the first word, 1 for the second, and so on. i Which pair of embedding dimensions we're filling in (pair 0, pair 1, … up to d/2 pairs total). d The total number of dimensions in the embedding (e.g., 512 or 768). Each pair of dimensions gets one sine and one cosine value. 100002i/d A wavelength multiplier. Small i gives a small divisor and fast oscillation, which captures nearby positions. Large i gives a large divisor and slow oscillation, which captures far away structure.

Intuition: Imagine encoding a position like binary. You would need fast changing bits for the ones place and slow changing bits for high order digits. Sine/cosine waves at different frequencies do the same thing, but smoothly. Each position gets a unique "fingerprint" made of wave values.

The Limitation

The model receives embedding + PE as input. But this means position is mixed into the token vector before attention begins. Sinusoidal PE has useful wave structure, so it can support relative distance, but attention must still learn how to read that structure from the added vectors. RoPE puts relative distance directly inside the query and key comparison used by attention.

Section 03: The RoPE Idea

RoPE: Encoding Position by Rotating, Not Adding

RoPE takes a completely different approach. Instead of adding a position vector to the token embedding before attention, it modifies the query and key vectors during attention by rotating them.

What are Queries and Keys?

Inside every attention layer, each token's embedding is projected into three vectors using learned weight matrices:

Query (q) "What information am I looking for from other tokens?" Key (k) "What information do I have to offer other tokens?" Value (v) "The actual content I pass along once selected."

The attention score between token A and token B is just q_A · k_B (a dot product). RoPE modifies q and k before this dot product.

The Core Idea: Dimension Pairs

RoPE treats the embedding as a sequence of 2D slices. If your embedding has 512 dimensions, RoPE sees it as 256 pairs: (dim 0, dim 1), (dim 2, dim 3), …, (dim 510, dim 511).

Each pair (x2i, x2i+1) is treated as a point in a 2D plane, like an (x, y) coordinate. Then, for a token at position m, RoPE rotates that 2D point counterclockwise by angle m · θᵢ.

Why dimension pairs matter

A single number cannot rotate by itself. Rotation needs a plane, so RoPE groups dimensions into pairs and rotates each pair as one tiny 2D coordinate system. This matters because every pair keeps two things at once: the content stored in that slice and the angle added by position. Different pairs rotate at different speeds, which lets attention compare nearby tokens using fast pairs and far apart tokens using slow pairs. The full embedding is the combination of all those small planes that carry position information.

What is the original x?

The original x is not the raw word. The model first turns the token into an embedding, then a learned matrix converts that embedding into a query or key vector. RoPE takes one slice with two numbers from that query or key vector and calls it x = (x₂ᵢ, x₂ᵢ₊₁). In the rotation diagram, the purple arrow is this original slice before RoPE changes it. Position starts at m = 0 for the first token, so the first token receives zero rotation and stays exactly where it began.

The Rotation Formula

For dimension pair i, token at position m:

  θᵢ  = 10000−2i/d     ← the rotation speed for this pair
  φ  = m · θᵢ           ← the angle to rotate by (proportional to position)

  x'2i = x2i · cos(φ) − x2i+1 · sin(φ)
  x'2i+1 = x2i · sin(φ) + x2i+1 · cos(φ)
This is just a standard 2D rotation matrix applied to the pair (x₂ᵢ, x₂ᵢ₊₁).

What to Notice

1
At position 0, the rotation angle is 0, so the vector is unchanged. RoPE says "position 0 means no rotation."
2
Each step in position adds a fixed angle of θᵢ radians. Position 1 → rotate by θᵢ. Position 2 → rotate by 2θᵢ. And so on.
3
Try changing the dimension pair i. Higher i gives smaller θᵢ, which means slower rotation. Low index pairs spin fast; high index pairs spin slowly. This is the multiple scale trick explained in Section 6.
4
The vector's length never changes. Rotation only changes direction, not magnitude. This is a key advantage over additive PE, which distorts the embedding's magnitude.

Why rotation? Because rotation has a beautiful algebraic property: when you compute the dot product of two rotated vectors, the absolute rotation angles cancel out and only the difference remains. This is the key insight, and we prove it interactively in Section 4.

Section 04: The Key Insight

Why Rotation Gives Relative Positions "For Free"

This is the heart of RoPE. Let's trace exactly what happens when two rotated vectors are dotted together during attention.

Quick reminder: what's a dot product?

Dot Product = Similarity

Given two vectors a = [a₁, a₂] and b = [b₁, b₂], the dot product is a · b = a₁b₁ + a₂b₂. Geometrically, it equals |a| |b| cos(angle between them). A large positive dot product means the vectors point in similar directions (the tokens are "similar" or "relevant" to each other). In attention, this score decides how much one token attends to another.

The math, step by step

Let q = query at position m, k = key at position n.
After RoPE: q̃ = R(mθ)·q,  k̃ = R(nθ)·k

q̃ · k̃ = (q₁k₁ + q₂k₂)·cos(m−n)θ
      + (q₁k₂ − q₂k₁)·sin(m−n)θ

= f(q, k, m−n). Only the relative position (m−n) appears!

The derivation uses the cosine identity for subtracting angles: cos(mθ−nθ) = cos((m−n)θ). The absolute positions m and n vanish. Only their difference survives.

The compass needle analogy. Imagine two compass needles, each pointing in some direction. Their relative angle is what matters for how "similar" they are. Now rotate both needles by the same amount. The relative angle between them doesn't change. RoPE does exactly this: rotating q by mθ and k by nθ is like rotating both needles by their respective positions. When you compute the dot product, only the difference in rotation (m−n)θ survives.

Why does this matter? Standard PE gives the model absolute positions ("this word is at position 42"), and the model must learn what "being 5 apart" means from training data. RoPE bakes in relative position at the mathematical level. The dot product is literally a function of (m−n). The model gets relative positions for free, without having to learn them.

Section 05: Prediction

How the Model Actually Predicts the Next Word

RoPE helps attention understand word order, but attention is only one part of prediction. The model does not simply find the nearest point, and it does not simply pick the word with the smallest angle difference. Dot products are used, but they are used in two different places.

1
Tokens become vectors
The prompt is split into tokens. Each token is converted into an embedding, which is a learned vector that represents that token in context.
2
Attention compares tokens
Each query is compared with allowed keys using dot products. In next word prediction, future tokens are masked out, so a token can only use earlier context.
3
Scores become weights
The dot product scores are passed through softmax. This turns them into attention weights, which say how much information to copy from each previous token.
4
Layers refine context
Many attention and feedforward layers repeat this process. The final vector at the last position becomes the model's summary of what should come next.
5
Vocabulary is scored
A final learned matrix gives every possible next token a score. Softmax converts those scores into probabilities, then decoding picks or samples the next token.
So is it nearest neighbor?

No. Attention dot products compare query and key vectors so the model can decide which earlier tokens matter. The final vocabulary scores are also comparisons similar to dot products with learned output vectors. But the model does not run a geometric nearest neighbor search over the plotted RoPE points.

So is it smallest angle?

No. Angle is a useful picture because a dot product rewards vectors that point in similar directions. In real models, vector length matters too, and the learned matrices can reshape the space. RoPE changes the direction of query and key slices so those dot products include word order.

Where RoPE fits: RoPE happens before the attention dot products. It changes the query and key vectors so attention scores depend on both meaning and relative position. The final word choice still comes from vocabulary probabilities after all transformer layers have finished processing the context.

Section 06: Multiple Scales

Multiple Frequencies: A Ruler at Every Scale

So far we've talked about one dimension pair rotating at one speed. But a real embedding has d/2 pairs, and each one rotates at a different speed, controlled by θᵢ:

θᵢ = 10000−2i/d
i = 0 → θ ≈ 1.00 (fastest, completes a full rotation in ~6 positions)
i = 1 → θ ≈ 0.18 (slower)
…
last pair, i = d/2 − 1 → θ is near 0.0001 (slowest, barely rotates across thousands of positions)
The Clock Analogy

Think of a digital clock: 12:34:56. The seconds digit ticks fast and distinguishes nearby moments. The minutes digit is slower and helps you know roughly when in the hour you are. The hours digit is slowest and gives coarse structure.

RoPE's dimension pairs work the same way. Fast rotating pairs (low i) are like seconds. They can tell apart tokens that are 1 or 2 positions away. Slow rotating pairs (high i) are like hours. They distinguish tokens hundreds of positions apart. Together, all d/2 pairs give the model a rich ruler across multiple scales.

Why this helps with long sequences. When a model is trained on sequences of length 2048 and then given a sequence of length 4096, the fast rotating pairs (which wrap around quickly) may be confused. The slow rotating pairs are still meaningful. RoPE degrades gracefully, unlike learned PE which has never seen those position IDs at all.

Section 07: Summary

RoPE vs. Sinusoidal PE: Side by Side

Both methods solve the same core problem. Here's how they differ in practice:

Property Sinusoidal PE (original Transformer) RoPE (LLaMA, Mistral, GPT-NeoX…)
How position is injected A position vector is added to the token embedding at the start Query and key vectors are rotated inside each attention layer
What the model learns Must learn how to use the added absolute position signal Relative distance is baked into dot products algebraically, with nothing extra to learn
Relative positions ⚠ Available through wave structure, but not directly in the attention score ✓ Explicit, because (m−n) appears directly in every dot product
Embedding magnitude ✗ Adding PE changes the vector's length ✓ Rotation preserves length exactly
Longer sequences than training ⚠ Fixed waves can extend, but behavior beyond training can still degrade ✓ Slow frequency pairs remain informative
Extra learned parameters None (or many, in the "learned PE" variant) ✓ None, because the formula is fixed
Used in Original Transformer, BERT, early GPT models LLaMA 2 & 3, Mistral, Falcon, Gemma, PaLM 2, and essentially all modern LLMs

The big picture: RoPE's genius is that it encodes position in a way that's invisible to the model's weights but perfectly legible to the attention mechanism. Every time two tokens compare their queries and keys, the relative distance between them is already there, encoded in the rotation angle with no extra learning required. That's why it has become the standard in virtually every transformer built since 2022.
