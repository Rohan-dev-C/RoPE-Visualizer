Section 01

Why Attention Needs Position

Content-only self-attention processes tokens in parallel. Without position information, reordering the input just reorders the corresponding outputs, so attention has no built-in notion of first, second, third, etc.

What is a token?

A token is the smallest chunk the model works with. It can be a word or part of a word.

Each token becomes an embedding, which is a list of numbers that stores meaning.

What is attention?

Self attention lets each token compare itself with the other tokens. The model gives higher weight to tokens that seem more useful for context.

So what's the problem?

Attention scores are computed by taking a dot product between query and key vectors.

This can tell whether two token vectors match, but it does not say which one came first.

Unless position is injected, the same token-content comparisons are reused when the order changes.

Order matters. Cat chased dog and dog chased cat use the same words, but they mean different things.

The model needs position to tell the roles apart.

The fix
1
Add a position signal so the model can tell where each token sits.
2

3

Section 02

Standard Sinusoidal Positional Encoding

The original Transformer used sine and cosine waves to build a position vector. That vector gets added to the token embedding.

The Formula

PE(pos, 2i) = sin( pos / 100002i/d )
PE(pos, 2i+1) = cos( pos / 100002i/d )
new_embedding = token_embedding + PE(pos, :)

What the terms mean.

pos The token position. The first token is 0. i The dimension pair being filled. d The total embedding size. 100002i/d A scale factor. Low pairs change fast. High pairs change slowly.

Intuition. Fast waves help separate nearby positions. Slow waves help track longer distances. Together they make a useful position code.

The Limitation

The model receives embedding + PE as input. This means position is mixed into the token vector before attention begins.

Sinusoidal PE has useful wave structure.

Attention still has to learn how to use that structure. RoPE puts distance directly into the query and key comparison.

Section 03

RoPE Encodes Position by Rotating

RoPE does not add a position vector to the token. It rotates the query and key vectors before attention scores are computed.

What are Queries and Keys?

Inside every attention layer, each token's embedding is projected into three vectors using learned weights.

Query (q) What this token is looking for. Key (k) What this token offers. Value (v) The content passed along after attention is weighted.

The attention score is q_A · k_B. RoPE changes q and k before this score is computed.

Dimension pairs

RoPE treats the embedding as a sequence of 2D slices. If an embedding has 512 dimensions, RoPE sees it as 256 pairs.

The pairs are dim 0 with dim 1, dim 2 with dim 3, and so on.

Each pair (x2i, x2i+1) is treated as a point in a 2D plane. For a token at position m, RoPE rotates that 2D point.

The rotation angle is m · θᵢ.

Why dimension pairs matter

A single number cannot rotate by itself. Rotation needs a plane, so RoPE groups dimensions into pairs.

Each pair keeps content and position together. Fast pairs help nearby tokens. Slow pairs help longer distances.

What is the original x?

The original x is a two number slice of a query or key vector. It is not the raw word.

The purple arrow shows this slice before RoPE. Position starts at m = 0, so the first token gets no rotation.

The Rotation Formula

For dimension pair i and token position m

  θᵢ  = 10000−2i/d     ← the rotation speed for this pair
  φ  = m · θᵢ           ← the angle to rotate by (proportional to position)

  x'2i = x2i · cos(φ) − x2i+1 · sin(φ)
  x'2i+1 = x2i · sin(φ) + x2i+1 · cos(φ)
This is a normal 2D rotation applied to one pair.

What to Notice

1
At position 0, the angle is 0. The vector does not move.
2
Each position step adds another θᵢ radians.
3
Higher dimension pairs rotate more slowly. This gives the model multiple scales.
4
The vector length stays the same. Rotation changes direction, not size.

Why rotation? When two rotated vectors are compared, the score depends on their position difference. That is the key idea.

Section 04

Why Rotation Gives Relative Position Directly

RoPE makes attention depend on the signed relative offset between tokens.

Dot Product

Dot Product = Similarity

Given two vectors a = [a₁, a₂] and b = [b₁, b₂], the dot product is a · b = a₁b₁ + a₂b₂.

A larger score means the vectors match better. In attention, this controls how much one token uses another token.

The math, step by step

Let q = query at position m, k = key at position n.
After RoPE  q̃ = R(mθ)·q,  k̃ = R(nθ)·k

q̃ · k̃ = (q₁k₁ + q₂k₂)·cos((m−n)θ)
      + (q₁k₂ − q₂k₁)·sin((m−n)θ)

= f(q, k, m−n). Only the signed relative offset remains.

The absolute positions cancel out. The signed gap m−n stays. Some slides write n−m depending on convention; the key idea is that only the relative offset matters.

Simple picture. Think of two arrows. Their relative angle matters.

RoPE rotates each arrow by its token position. When attention compares them, the score keeps the gap.

Verify It Yourself

Section 05

How the Model Actually Predicts the Next Word

RoPE helps attention use word order.

It does not pick the next word by finding the nearest point or the smallest angle. Prediction uses several steps.

1
Tokens become vectors
The prompt is split into tokens. Each token becomes a vector.
2
Attention compares tokens
Queries and keys are compared with dot products. Future tokens are hidden.
3
Scores become weights
Softmax turns scores into weights. Higher weights mean more attention.
4
Layers refine context
Many layers repeat this. The last vector summarizes the context.
5
Vocabulary is scored
The last vector is compared with learned vocabulary vectors. Decoding picks or samples one token.
So is it nearest neighbor?

No. Attention uses dot products to decide which earlier tokens matter.

The final word comes from vocabulary scores and decoding, not a nearest point search.

So is it smallest angle?

No. Angle is only part of the picture.

Vector length and learned weights matter too. A small angle is not the rule used to pick a word.

Where RoPE fits. RoPE happens before attention scores.

It helps attention use meaning and relative position. The final word still comes from vocabulary probabilities.

Section 06

Multiple Frequencies Make a Ruler

A real embedding has many dimension pairs. Each pair rotates at a different speed.

θᵢ = 10000−2i/d
i = 0 → θ ≈ 1.00 (fast)
i = 1 → θ ≈ 0.18 (slower)
…
later pairs → θ is very small (very slow)
The Clock Analogy

A clock has fast and slow hands. The second hand changes quickly. The hour hand changes slowly.

RoPE uses the same idea.

Fast pairs help with nearby tokens. Slow pairs help with longer distances.

Together they give the model a ruler with many scales.

Why this helps. Fast pairs can wrap around. Slow pairs change less, so they still carry useful position information at longer distances.

Section 07

RoPE and Sinusoidal PE

Both methods add position information. They do it in different places.

Property Sinusoidal PE (original Transformer) RoPE (LLaMA, Mistral, GPT-NeoX…)
How position is injected A position vector is added to the token embedding at the start Query and key vectors are rotated inside each attention layer
What the model learns Must learn how to use the added absolute position signal The relative distance term appears in dot products by formula
Relative positions ⚠ Available through wave structure, but not as an explicit single gap term in the basic attention score ✓ Explicit, because (m−n) appears directly in every dot product
Embedding magnitude ✗ Adding PE changes the vector's length ✓ Rotation preserves length exactly
Longer sequences than training ⚠ Fixed waves can extend, but behavior beyond training can still degrade ⚠ The formula extends, but very long context often needs scaling or fine tuning
Extra learned parameters None, or many in learned PE variants ✓ None, because the formula is fixed
Used in Original Transformer used fixed sinusoidal PE; BERT/GPT-style models often used learned absolute position embeddings instead Many modern decoder LLMs use RoPE-style rotary embeddings

The big picture. RoPE encodes position in a way attention can use directly.

When two tokens compare query and key vectors, their signed relative offset is already part of the score.
